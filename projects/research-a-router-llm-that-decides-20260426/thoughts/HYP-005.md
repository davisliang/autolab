## Gap this fills

Every paper in the survey (FrugalGPT, RouteLLM, Hybrid LLM, AutoMix, RouterBench) and every existing hypothesis (HYP-001 through HYP-004) optimizes the cost-quality tradeoff only. Latency is acknowledged as a risk in HYP-002 but never modeled as a first-class objective. In production interactive settings—chatbots, coding assistants, real-time Q&A—P95 response time is an SLA constraint, not a secondary concern. A router that cannot enforce latency budgets is not deployable in the most latency-sensitive 30% of production use-cases.

## Mechanism

1. **Per-tier latency model**: Maintain a per-model-tier EWMA latency tracker updated after each observed API call:
   ```
   L̂_t(tier) = α · observed_latency + (1−α) · L̂_{t-1}(tier),  α = 0.1
   ```
2. **Latency-constrained tier selection**: At routing time, compute the cost-quality-optimal tier `t*` from a standard RouteLLM-style scorer. If `L̂_t(t*) > SLA_budget`, override with the cheapest tier whose EWMA latency estimate is within SLA.
3. **Quality guard**: If all tiers exceed SLA, route to cheapest tier and flag the response as SLA-breached (logged; not shown to user).
4. **SLA calibration**: SLA threshold set at deployment as the 95th percentile of acceptable wait time for the target application; default = 2000 ms.

## Experiment setup

- Query set: 500 queries sampled from MMLU + OpenAssistant (interactive mix).
- Simulate real latency variation by introducing controlled artificial delays scaled to real Haiku/Sonnet/Opus API latency distributions from RouterBench (LIT-021) data.
- Measure P95 latency and mean quality (LLM-judge vs. Opus-only gold) over the full run.
- Baseline: RouteLLM-style cost-only router (ignores latency).

## Pre-registered prediction

`p95_latency_reduction_ratio ≥ 0.25` (≥25% reduction in P95 latency vs. cost-only baseline).  
Mean quality must remain within 2% of the cost-only baseline (secondary constraint).  
Direction: **greater**.

## Why this is novel

No existing routing paper treats latency as a first-class routing signal or proves that EWMA-based latency awareness can enforce SLA budgets without material quality loss. The structural parallel to network congestion control (TCP CWND estimation via RTT EWMA) suggests the mechanism is sound from first principles.

## Risks

- API latency distributions are bursty; EWMA may underestimate 99th-percentile spikes.
- Simulated latency may not fully capture real CDN/geo-routing variance.
- Quality penalty from forced downgrade (when all tiers miss SLA) needs to be bounded.
