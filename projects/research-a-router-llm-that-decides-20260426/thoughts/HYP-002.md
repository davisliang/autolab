## Motivation

Upfront routers commit to a tier before seeing any model output. Cascades allow cheap models to self-triage: if Haiku answers with high confidence, no escalation occurs. This exploits the fact that many queries *look* hard from text features but are trivially solved by small models.

## Mechanism

1. Send every query to Haiku.
2. Compute confidence as `exp(mean(log-probs of output tokens))` on the generated answer.
3. If confidence < τ₁ (tuned on validation set), re-run with Sonnet.
4. If Sonnet confidence < τ₂, re-run with Opus.
5. Thresholds τ₁, τ₂ selected on validation split to maximize cost_normalized_quality.

**cost_normalized_quality** = quality_score / normalized_api_cost_fraction
where quality_score = LLM-judge agreement rate with Opus-only gold answers.

## Baseline

Flat upfront router from HYP-001 (multi-signal LightGBM).

## Pre-registered prediction

`cost_normalized_quality(cascade) / cost_normalized_quality(flat_router) ≥ 1.15`.
Direction: **greater**.

## Risks

- Token log-probs from API may be poorly calibrated.
- Cascade latency is additive on escalated queries; tail latency needs measurement.
