## Motivation

Supervised routing requires labeled examples of query difficulty, which is expensive to collect. If the entropy of cheap-model outputs reliably proxies task difficulty, routing training data can be generated automatically at scale—dramatically lowering deployment cost on new domains.

## Mechanism

1. For each query in an unlabeled corpus, sample k=5 completions from Haiku.
2. Compute token-level entropy over the completions (normalized by mean response length).
3. Threshold entropy to assign ternary difficulty labels: low → Haiku, medium → Sonnet, high → Opus.
4. Train the same LightGBM router from HYP-001 on these auto-generated labels.
5. Compare routing_accuracy of self-supervised vs. supervised variant on a human-labeled held-out test set.

## Pre-registered prediction

`routing_accuracy(supervised) - routing_accuracy(self_supervised) ≤ 0.05` (gap ≤ 5pp).
Direction: **less**.

## Why this matters

If confirmed, any deployment can bootstrap a routing dataset at the cost of 5k cheap Haiku calls with no human annotation—cutting routing dataset cost by ~95%.

## Risks

- Haiku entropy may be high for creative/open-ended queries regardless of actual difficulty, conflating uncertainty with difficulty.
- Must control for token-length bias in entropy calculation.
