## Motivation

Raw sentence embeddings capture semantic content but conflate query difficulty dimensions that matter for model routing:
- **Syntactic complexity**: deeply nested dependency structures demand stronger reasoning.
- **Entity density**: high NER count suggests knowledge-intensive queries that benefit from Opus.
- **Reasoning pattern**: presence of "if...then", "compare", "explain why" signals multi-step reasoning.
- **Domain difficulty**: some domains (math, law, medicine) consistently require larger models.

## Feature Engineering

| Feature | Extractor | Dim |
|---------|-----------|-----|
| Sentence embedding | all-MiniLM-L6-v2 | 384 |
| Dependency parse depth | spaCy en_core_web_sm | 1 |
| Max NER span count | spaCy | 1 |
| CoT indicator words | keyword list | 5 |
| Domain embedding | topic model (BERTopic, 20 topics) | 20 |

Total feature dim: 411. Train same 2-layer MLP as HYP-001 for fair comparison.

## Prediction

- Metric: `routing_f1` (macro-averaged F1 across {Haiku, Sonnet, Opus} classes)
- Threshold: ≥4pp improvement (0.04 absolute) over embedding-only baseline (HYP-001 classifier)
- Direction: `greater`

## Dataset

Construct routing labels from oracle routing: cheapest model achieving ≥Sonnet quality on MMLU. Use 3:1 train:test split, stratified by domain.

## Confounders

- Linguistic features are cheaper but noisier than neural embeddings; test ablation of each feature group.
- spaCy parse adds ~2ms; profile to ensure routing overhead stays < 5ms total.
