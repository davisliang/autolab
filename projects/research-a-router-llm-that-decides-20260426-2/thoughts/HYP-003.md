## Motivation

Static routing classifiers trained offline fail when query distributions shift (e.g., new domain, seasonal topics). A contextual bandit formulation allows the router to continuously update its policy as it observes reward signals (quality scores from downstream evaluation). This is especially valuable in production settings where query distributions evolve.

## Method

1. Use LinUCB (Linear Upper Confidence Bound) with query embedding as context vector.
2. Reward = quality score of routed model's response (measured via automated judge or exact match).
3. Exploration: UCB term encourages routing to uncertain arms (models) until confidence is established.
4. Compare against: static MLP classifier (HYP-001), random routing, always-best.

## Pre-registration

- OOD test set: MMLU categories held out from training; also ARC-Challenge as secondary OOD.
- Routing accuracy = fraction of queries routed to the "oracle-best" tier (cheapest model meeting quality floor).
- Metric: `routing_accuracy_ood` on held-out splits.
- Threshold: ≥3pp improvement (0.03 absolute) over static classifier on OOD sets.
- Direction: `greater`.

## Why LinUCB

LinUCB has closed-form updates (no gradient descent), O(d²) per update where d = embedding dim, and well-understood regret bounds. Suitable for streaming inference with minimal overhead.

## Confounders

- Reward delay: in practice, quality scores may lag by a batch. We simulate 1-step lag in experiments.
- Exploration cost: UCB exploration occasionally routes cheap queries to Opus. Budgeted exploration variant tested.
