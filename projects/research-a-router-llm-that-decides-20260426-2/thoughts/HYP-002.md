## Cross-domain transplant origin

Speculative decoding (Leviathan et al. 2023, Chen et al. 2023) uses a small draft model to propose tokens and a large model to verify them in batch — achieving speedups without quality loss. We transplant this draft-then-verify pattern to the routing setting across separate API calls:

- **Draft**: Haiku generates an answer.
- **Verify**: A lightweight classifier (or the answer's own internal confidence proxy) decides if the Haiku answer is "good enough."
- **Escalate**: If not, route to Sonnet; if Sonnet's confidence is also low, escalate to Opus.

## Method

1. Send query to Haiku; compute confidence signal: (a) log-probability of first token, (b) answer length consistency, (c) answer self-consistency (3 samples, cheap).
2. Threshold calibration on a held-out set to decide escalation criteria.
3. Escalate to Sonnet if confidence < θ_1; escalate to Opus if Sonnet confidence < θ_2.
4. Tune θ_1, θ_2 on calibration split to meet quality floor.

## Prediction

- Metric: `cost_reduction_pct` = 1 - (cascade cost / always-Sonnet cost)
- Threshold: ≥10% cost reduction
- Direction: `greater`
- Constraint: quality degradation ≤1% absolute on MMLU accuracy

## Why this beats static classifiers

Static routing requires a query-time embedding + classifier. The cascade uses the model's own output as the confidence signal — no separate embedding step. It also adapts automatically to model capability drift.

## Confounders to control

- Self-consistency requires 3 Haiku samples; cost model includes these.
- Measure against both always-Sonnet and always-Haiku baselines.
