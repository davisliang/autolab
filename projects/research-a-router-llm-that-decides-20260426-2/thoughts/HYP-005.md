## Motivation

Current routing approaches use a fixed routing policy independent of user budget constraints. In practice, operators have varying cost tolerance. A utility-maximizing router that exposes a single λ (cost-sensitivity) knob allows continuous interpolation between always-Haiku and always-Opus, tracing out an empirical Pareto frontier that should dominate all fixed-threshold strategies.

## Method

1. **Calibration**: run a random sample of queries through all 3 models; fit a Gaussian Process or isotonic regression to map (query features, model) → (expected_quality, cost).
2. **Routing policy**: for each query and given λ, pick model = argmax_m [predicted_quality(q, m) - λ · cost(m)].
3. **Evaluation**: sweep λ ∈ {0.0, 0.1, 0.25, 0.5, 1.0, 2.0, 5.0, 10.0} (8 budget levels). For each λ, compare (cost, quality) point against fixed-threshold router operating at same average cost.
4. **Pareto dominance**: a point (c_1, q_1) dominates (c_2, q_2) if c_1 ≤ c_2 and q_1 ≥ q_2 with at least one strict inequality.

## Prediction

- Metric: `pareto_dominance_ratio` = fraction of the 8 budget levels where utility-maximizing router Pareto-dominates fixed-threshold baseline
- Threshold: ≥0.60 (dominates at ≥5 of 8 budget levels)
- Direction: `greater`

## Baselines

1. Fixed-threshold router: route Haiku if token_count < 50, Opus if > 200, else Sonnet.
2. Always-Sonnet (cost and quality anchor).
3. Oracle Pareto frontier (upper bound).

## Confounders

- GP calibration requires ~200 samples; control for calibration set size.
- Quality scores are noisy; use 95% CI in dominance assessment.
