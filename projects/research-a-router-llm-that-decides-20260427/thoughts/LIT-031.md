## Relevance to HYP-003

This paper is the strongest external motivation for HYP-003's multi-signal feature approach. Key finding: existing BERT/embedding-based routers route based on **category identity** rather than **query difficulty within a category**. A simple arithmetic question and a complex tensor calculus question both get routed to Opus because they are "math."

HYP-003's syntax features (token count, vocabulary entropy, type-token ratio) directly target this failure: they capture within-category difficulty without requiring category labels. A short, common-vocabulary math question scores differently from a long, technical-vocabulary one — even within the same category.

## Positive Signal for HYP-003

The paper argues implicitly for exactly what HYP-003 proposes: routing signals that capture intrinsic query complexity (surface features) rather than just semantic similarity to training examples (embedding category centroids). This validates HYP-003's inclusion of explicit syntax features alongside embeddings.

## Novel Contribution Path

No existing paper demonstrates that adding syntax features to an embedding-based router fixes the "all-hard-category-goes-to-Opus" failure mode identified here. HYP-003 can:
1. Reproduce the DSC failure with a pure-embedding baseline on MMLU
2. Show syntax features improve routing on simple-within-hard-category subsets
3. Quantify cost savings from this differential improvement

This constitutes a concrete, falsifiable contribution that directly responds to this paper's gap.

## Benchmark Design Implication

The DSC benchmark's emphasis on simple instances within hard categories directly applies to MMLU, which has both easy and hard questions within each subject area. Evaluating HYP-003 on difficulty-stratified MMLU subsets would reveal whether syntax features help where embeddings fail — making the evaluation more informative than aggregate routing accuracy.
