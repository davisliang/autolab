## Why This Matters for HYP-001

CRIT-001's proposed fix for HYP-001 was: "pivot to novel routing signals (embeddings + confidence bounds, production-log datasets, etc.)." TRACER is precisely this — it uses LLM API outputs as oracle labels, solving HYP-001's labeled-data prerequisite problem without a separate labeling pipeline.

## Key Insight: LLM as Labeling Engine

TRACER reframes the relationship between LLMs and classifiers:
- Instead of training a classifier first and deploying it as the router, TRACER starts with the LLM as the primary router
- Every LLM call produces a labeled example for free (the LLM's response is the label)
- As traces accumulate, a lightweight surrogate progressively absorbs more traffic
- The parity gate ensures the surrogate only routes when it agrees with the LLM

## Connection to HYP-001's Oracle Label Problem

HYP-001 requires "labeled MMLU routing dataset with oracle model labels" (prerequisite). TRACER's approach sidesteps this:
1. Start with Haiku-as-router (the HYP-001 baseline) making routing decisions
2. Collect (query, routing_decision) pairs as free traces  
3. Train a DistilBERT surrogate on these traces
4. Deploy surrogate only when it agrees with Haiku above threshold

This is a novel formulation: **HYP-001 reversed** — use Haiku routing decisions as training labels for the classifier, then deploy classifier to replace Haiku router. No separate oracle label construction needed.

## Performance Numbers

At Sonnet 4.6 pricing ($3/M input, $15/M output), TRACER achieves:
- Banking77: $2.60/1000 teacher calls → $0.44/1000 at 83.2% coverage (83% cost reduction)
- CLINC150: 100% cost reduction (surrogate fully replaces teacher)

For HYP-001 context: if Haiku-as-router costs $0.00025/routing call, a TRACER-style surrogate trained on those calls would eliminate that overhead cost while maintaining routing quality.

## Parity Gate as Quality Guard

The parity gate (α-threshold on held-out surrogate-teacher agreement) is more principled than HYP-001's post-hoc accuracy evaluation. This is a directly adoptable design element for HYP-001's experimental protocol.
