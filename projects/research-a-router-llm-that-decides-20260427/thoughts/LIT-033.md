## Why This Matters for HYP-001

HYP-001's prerequisite is "labeled MMLU routing dataset with oracle model labels" — requiring expensive multi-model inference to construct training data. This paper proposes a complementary signal that works without labels.

The cross-model perplexity signal (how surprised a verifier model is when reading the generating model's answer) can serve as:
1. A proxy routing signal without needing oracle labels — reducing HYP-001's data construction cost
2. A comparison baseline: does supervised DistilBERT routing beat a training-free CMP-based escalation rule?

## Key Mechanism

For any query q answered by Haiku:
- Feed Haiku's answer to a verifier (e.g., a small local model)
- Measure perplexity or entropy of the verifier over Haiku's answer tokens
- High verifier perplexity → Haiku's answer is surprising/uncertain → escalate to Sonnet

This is an output-conditioned signal (like HYP-002's speculative cascade) but without the structural overhead of running the draft model first, since it uses a local verifier rather than an API model.

## Relevance to CRIT-001's Proposed Fix

CRIT-001 suggested "pivot to novel routing signals (embeddings + confidence bounds, production-log datasets, etc.)." CMP is exactly such a novel signal — label-free correctness estimation that doesn't require training on (query, optimal_model) pairs.

## Limitation

CMP routes after observing Haiku output (output-conditioned) — different from HYP-001's pre-inference routing. But as a baseline or signal to combine with query features, it establishes a label-free routing ceiling that HYP-001's supervised approach should aim to exceed.
