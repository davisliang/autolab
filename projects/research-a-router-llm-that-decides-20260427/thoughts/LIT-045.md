## Summary

RouterBench (Bieker et al., 2024) introduces a standardised evaluation framework for LLM routing: 405,000 pre-generated inference outcomes from 11 models across 8 datasets including MMLU. It proposes a cost-quality tradeoff metric (CQ-score) that directly connects routing decisions to API cost savings at matched quality. Predictive routers (classifiers on input embeddings) consistently achieve 2-5× cost reduction over single-model strategies on MMLU.

RouterBench separates predictive routing (input-feature only, like HYP-003) from non-predictive routing (cascade/output-based). The benchmark exposes that predictive routers generalise poorly to complex tasks and newer models — a direct critique point for HYP-003.

## Key Claims

1. A standardised cost-quality metric bridges routing accuracy to real cost savings: a 1pp routing accuracy gain ≈ 2-3% cost savings on MMLU at typical Haiku/Sonnet/Opus price ratios.
2. Predictive embedding classifiers achieve 2-5× cost reduction on MMLU — confirming the embedded-feature approach works.
3. Routing generalisation to complex tasks (multi-step reasoning, multi-domain) degrades significantly vs simple factual QA — HYP-003 must address OOD performance.
4. Syntax features (length, complexity) are not evaluated as standalone routing signals in RouterBench; their incremental value remains an open empirical question.

## Relevance to HYP-003

RouterBench provides the key bridge between routing accuracy and cost efficiency that CRIT-004/CRIT-010 demand: the CQ-score metric translates routing accuracy predictions to cost savings estimates. This means HYP-003's 85% routing accuracy target can be converted to an expected ~2.5× cost reduction on MMLU at typical API prices. Additionally, RouterBench's MMLU subset provides the oracle labels HYP-003 needs for training and evaluation.

## Limitations

- Pre-generated outcomes may not reflect current Haiku/Sonnet/Opus performance distributions.
- Syntax features not benchmarked; no ablation of feature types.
- Focus on binary routing (small/large); 3-tier extension requires additional oracle label construction.
