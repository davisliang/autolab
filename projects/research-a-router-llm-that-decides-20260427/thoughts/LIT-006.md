## RouteLLM — Relevance to HYP-003 (Speculative Routing)

RouteLLM (Ong, Almahairi et al., UC Berkeley / Anyscale 2024) is the strongest learning-based baseline for binary LLM routing. It is the direct **sequential pre-call routing baseline** that speculative routing competes against on latency.

### What RouteLLM does
- Trains a **win prediction model** P(win_strong | query) from human preference data (Chatbot Arena).
- At inference: compute router score → if score < threshold α route to weak (cheap) model, else to strong model.
- Key property: routes to **exactly one LLM per query**, so avoids the multi-LLM latency of cascade approaches.

### Key numbers
- **>2x cost reduction** at matched quality across MMLU, MT-Bench, GSM8K.
- Strong generalization to LLM pairs not seen during training (GPT-4 / Haiku routing works even when trained on GPT-4 / Mixtral).
- Multiple router architectures: matrix factorization, BERT-based similarity, causal LLM head.

### Relevance gap for HYP-003
RouteLLM's total wall-clock latency per query = **T_router + T_selected_model** (sequential). For Haiku-selected queries (≥50% of typical workloads), speculative routing eliminates T_router from the critical path by overlapping it with T_Haiku. RouteLLM explicitly notes that "routing to a single LLM minimizes cost and latency compared to multi-LLM approaches" — but still treats the router as a blocking prefix, not a concurrent operation.

**HYP-003 directly challenges the sequential assumption** by showing T_wall = max(T_router, T_Haiku) + (T_escalated if misrouted) is ≥15% faster than T_router + T_model.
