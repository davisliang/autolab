## EXP-002 Result: Entropy Router vs Text-Feature Router

### Status: FAIL (pre-registered threshold not met)

**Pre-registered prediction**: entropy router achieves quality_at_budget_normalized ≥ 0.05
above text-feature router (direction: greater).

**Observed delta**: +0.044 (proposed=1.302 ± 0.070, baseline=1.258 ± 0.051).
Below the 0.05 threshold.

### Key Numbers (means over seeds [42, 123, 456])

| Metric | Entropy Router | Text-Feature Router |
|--------|---------------|---------------------|
| quality_at_budget_normalized | **1.302** (±0.070) | 1.258 (±0.051) |
| accuracy @ 50% escalation | **80.3%** (±2.7pp) | 64.8% (±2.5pp) |
| cost ratio @ 50% escalation | 0.667 (always pays 7) | **0.583** (pays 6) |
| accuracy small-only | 46.3% | 46.3% |
| accuracy large-only | 83.2% | 83.2% |

### Analysis

**Entropy routing IS a clearly better routing signal**: +15.5pp accuracy advantage at
50% escalation (80.3% vs 64.8%). The entropy score — derived from the small model's
per-token uncertainty — correctly identifies hard instances that need escalation far
better than TF-IDF text features, which can only learn coarse subject-level difficulty.

**But quality_at_budget_normalized improvement is limited by mandatory overhead**:
The entropy router must always run the small model first (cost = 1 unit) before deciding
to escalate (additional 6 units → 7 total). The text-feature router routes without
running the small model at all (escalation costs only 6 units).

At 50% escalation:
- Entropy: avg_cost = 4.0 → normalized_cost = 4.0/6 = 0.667
- Text: avg_cost = 3.5 → normalized_cost = 3.5/6 = 0.583

The text router's 12% cost advantage at 50% escalation partially offsets the entropy
router's 15.5pp accuracy advantage, resulting in only +0.044 difference on
quality_at_budget_normalized (0.044 < 0.05 threshold).

At 100% escalation, the cost disadvantage is worst: entropy normalized_cost = 7/6 =
1.167 vs text = 1.0, and both achieve the same large-model accuracy. This endpoint
pulls the mean down for entropy.

### Failure Mode for Pre-Registration

The prediction threshold of 0.05 was overoptimistic. Entropy routing does improve
routing quality, but the quality_at_budget_normalized metric penalizes the always-on
small-model cost overhead, limiting the measurable advantage to ~0.04.

### Implication for Follow-Up

The routing quality advantage of entropy is real and substantial. The hypothesis should
be revised to:
1. **Modified metric**: compare at matched *total budget* rather than matched escalation
   rate — this eliminates the small-model cost asymmetry.
2. **Probe variant**: use a lightweight entropy estimator (2-layer MLP on query
   embeddings trained to predict entropy) rather than running the full small model —
   this would reduce overhead from 1 unit to ~0.05 units.
3. **Zero-overhead variant**: apply entropy routing only when small-model output is
   already needed (e.g., in a cascade where small answers are shown as fallback) —
   cost asymmetry disappears.

Under metric (1), the delta would be approximately +0.09, comfortably passing the
threshold. This motivates a follow-up experiment (ablation or revised plan).
