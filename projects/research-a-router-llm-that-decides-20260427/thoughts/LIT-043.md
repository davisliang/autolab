## Summary

ComplexityNet (2023) fine-tunes a small language model specifically to classify task complexity and route accordingly. Applied to MBPP (Python coding), it achieves 79% complexity prediction accuracy (vs 34% baseline without fine-tuning) and reduces compute resource usage by 90% relative to always using the largest model, while maintaining 86.7% code generation accuracy.

Unlike HYP-003's logistic regression on hand-crafted features, ComplexityNet learns complexity implicitly via fine-tuning — but the key result is the empirical link between complexity prediction accuracy and cost efficiency: 79% routing accuracy → 90% compute reduction. This provides a concrete precedent for the cost-efficiency payoff of routing accuracy gains.

## Key Claims

1. Task complexity is a learnable per-query property; a fine-tuned small model achieves 79% accuracy, far above unsupervised baselines.
2. 79% routing accuracy translates to 90% compute reduction vs always-large baseline — a 1pp routing accuracy gain yields substantial cost savings when difficulty distribution is skewed toward easy queries.
3. Oracle complexity labels (cheapest model meeting quality threshold) can be constructed without human annotation, from model evaluation outcomes alone.
4. The method generalises the principle behind HYP-003: complexity-based routing is empirically validated in the coding domain; MMLU provides analogous multi-domain challenge.

## Relevance to HYP-003

ComplexityNet directly validates the core premise of HYP-003: routing accuracy against oracle labels does translate to real compute/cost reduction. The 79% → 90% compute reduction result provides a calibration point: if HYP-003 achieves its predicted ≥85% accuracy on MMLU, a comparable or better cost reduction is plausible. However, ComplexityNet uses fine-tuning (not logistic regression on hand-crafted features), raising the question of whether lightweight features suffice for the more diverse MMLU domain.

## Limitations

- Single domain (MBPP coding); MMLU's 57-subject diversity is harder.
- Fine-tuned LM rather than logistic regression — higher accuracy but more expensive to train/deploy.
- No ablation of which features the model exploits; opaque complexity mechanism.
