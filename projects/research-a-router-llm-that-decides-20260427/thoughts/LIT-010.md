## Speculative Decoding (Leviathan et al., Google Research, ICML 2023) — Relevance to HYP-003

This paper is the **closest conceptual ancestor** of HYP-003. It directly transplants CPU branch prediction / speculative execution into LLM inference — the exact cross-domain transfer HYP-003 proposes for routing.

### What it does
- **Draft model** M_q (small, fast): generates γ candidate tokens autoregressively.
- **Target model** M_p (large, accurate): scores all γ tokens in parallel in one forward pass.
- **Speculative sampling**: accept/reject each draft token so that accepted tokens are distributed exactly as if sampled from M_p directly.
- If draft is good (agreement between M_q and M_p is high), the target model produces γ+1 tokens per forward pass instead of 1.

### Key results
- **2-3x wall-clock speedup** on T5-XXL (11B) over standard autoregressive decoding.
- Applied to 97M / 137B (LaMDA) models.
- Zero change to output distribution — exact method.

### Mechanism analogy to HYP-003
| Speculative Decoding | Speculative Routing (HYP-003) |
|---|---|
| Draft model generates γ token guesses | Haiku generates response speculatively |
| Target model verifies all drafts in parallel | Router decides commit vs. escalate in parallel |
| Commit if draft ≈ target | Commit Haiku if router says "Haiku" |
| Rollback if mismatch | Discard Haiku, call Sonnet/Opus if escalated |
| Speedup proportional to draft acceptance rate | Speedup proportional to Haiku selection rate |

### Key gap / distinction
Speculative decoding operates **within** a single LLM's generation loop (token-level); HYP-003 operates **across** different LLMs at the query level (router-level). Speculative routing is a novel application of the same principle at the API routing abstraction layer — not yet explored in the literature.
