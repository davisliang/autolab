## Why This Matters for HYP-001

HYP-001 proposes DistilBERT routing vs Haiku-as-router on cost efficiency. CRIT-001 flagged this as unnovel (FrugalGPT, RouteLLM already do classifier routing). But those baselines compare classifiers against "always use big model" — not against LLM-as-router.

This paper is the closest published work to HYP-001's exact comparison: it explicitly benchmarks SLM routing classifiers against LLM-based routers and finds LLM routers incur real overhead (2.3x latency, API cost per call) while SLMs have zero marginal cost. The competitive variable is accuracy, not cost or latency.

## Quantitative Anchors for HYP-001

| Metric | SLM (Qwen-2.5-3B) | LLM Router (DeepSeek-V3) |
|--------|-------------------|--------------------------|
| Accuracy | 79.3% | 83.0% |
| Latency (median) | 988ms | ~2300ms |
| Marginal cost | $0 (self-hosted) | API cost per call |
| Passes latency gate? | Yes | No (2295ms > 2000ms P95) |

## Gap Addressed by HYP-001

The 6-8pp accuracy gap remaining validates HYP-001's research angle. If HYP-001's DistilBERT achieves similar accuracy to a Haiku-as-router while eliminating routing overhead costs, cost efficiency (answers per dollar) will favor classifier routing. This paper quantifies what accuracy level LLM routing achieves and what latency it costs.
