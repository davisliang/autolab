## Motivation

The obvious baseline for query routing is to ask Haiku itself which model to use. But this incurs Haiku inference cost on every query—even trivially simple ones. A small text classifier (DistilBERT, ~66M params) can be fine-tuned offline on a labeled complexity dataset and runs locally at near-zero marginal cost per query.

## Claim

A distilbert-based text classifier trained to predict the cheapest model that still achieves ≥90% of Opus quality on each MMLU question (the "oracle label") will route queries with at least 15% better cost efficiency (correct MMLU answers / total API cost in USD) compared to the Haiku-as-router baseline, which pays Haiku inference overhead to make every routing decision.

## Why 15%?

- Haiku router pays ~$0.00025/1K tokens routing overhead per query.
- If 60% of queries are trivially simple (answerable by Haiku), saved inference cost compounds significantly over thousands of queries.
- Conservative estimate is 10–20% efficiency gain; we pre-register 15%.

## Experimental Design Notes

- Dataset: MMLU 5-shot (14K questions across 57 subjects)
- Oracle labels: run Haiku/Sonnet/Opus on each question; label with cheapest model achieving ≥90% of Opus score
- Train/test split: 80/20 stratified by subject
- Classifier: distilbert-base-uncased fine-tuned for 3-class routing (Haiku/Sonnet/Opus)
- Evaluation: cost_efficiency = correct_answers / total_api_cost_usd
- Baseline: Haiku-as-router (Haiku prompted "Which model should answer this: haiku/sonnet/opus?")

## Open Questions

- How stable are oracle labels across different Opus prompt variants?
- Does distilbert generalize to out-of-domain queries (coding, math)?
- What is the minimum labeled dataset size for reliable routing accuracy?
