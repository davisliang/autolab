## Experiment: Multi-Dimensional Routing vs Single-Score Baseline

### Overview

Test whether decomposing query complexity into 4 orthogonal dimensions
(reasoning depth, domain specificity, ambiguity, creativity) and routing
via a learned decision table outperforms a single-score logistic-regression
router trained on the same features.

### Data pipeline

1. **Query collection** (offline, cached):
   - Sample 500 queries each from MMLU (val), GSM8K (val), AlpacaEval → 1500 total.
   - Each query gets a ground-truth "best model" label: Haiku / Sonnet / Opus.
   - Ground-truth labels are derived from per-model accuracy on the benchmark:
     pick the cheapest model whose accuracy on that example equals the most
     expensive model that got it right. This gives oracle routing labels.

2. **Proxy oracle labels for 4 dimensions** (one-time generation):
   - Use a local heuristic labeller (keyword + regex rules + few-shot classifier
     on 200 hand-labelled examples) to assign binary labels for:
     - RD: multi-step reasoning required (math, code, logic chain)
     - DS: domain-specific knowledge required (STEM, law, medicine)
     - AMB: query admits multiple valid interpretations
     - CR: expected output is open-ended or stylistic
   - Rationale: avoids dependence on external LLM API for labels.

3. **Split**: 70% train / 15% val / 15% test, stratified by source dataset.

### Models

**Proposed (multi-head)**:
- Embed all queries with `all-MiniLM-L6-v2` (384-dim, runs on CPU in <1 min for 1500 queries).
- Train 4 independent `sklearn.linear_model.LogisticRegression` heads,
  one per dimension, on train split.
- Train a `sklearn.ensemble.RandomForestClassifier(n_estimators=50)` over
  the 4 head probabilities → 3-class output (Haiku / Sonnet / Opus).
- Hyperparams: `C=1.0, max_iter=1000` for each logistic head;
  RF with `max_depth=5, min_samples_leaf=10`.

**Baseline (single-score)**:
- Same `all-MiniLM-L6-v2` embeddings.
- Single `sklearn.linear_model.LogisticRegression(C=1.0, max_iter=1000)`
  trained directly on 3-class routing labels.
- Matched compute: identical embedding step, same train set, same eval.

### Evaluation

| Metric | Definition |
|--------|-----------|
| `routing_accuracy` | Fraction of test queries assigned to the oracle-best model |
| `cost_savings_ratio` | 1 − (predicted_cost / always_opus_cost) |
| `quality_at_matched_cost` | Average quality score at the same total cost as baseline |

Primary metric: `routing_accuracy` (HYP-002 predicts ≥3pp gain over baseline).

### Seeds & Reproducibility

- Seeds `[42, 123, 456]` control: train/val/test split, sklearn random_state,
  RF random_state.
- Report mean ± stddev across 3 seeds.
- `repro.sh` will be auto-generated.

### Sanity gate

Overfit-32: train on 32 examples, verify train loss drops ≥50% within 60s.
(Logistic regression converges near-instantly on 32 examples.)

### Ablation plan (triggered on pass)

If routing_accuracy gain ≥ 3pp confirmed:
- Ablate each dimension head individually (remove one head, retrain RF on
  remaining 3 probabilities) to test whether all 4 dimensions are necessary.
- This isolates the mechanism: if removing any single head drops accuracy
  back to baseline, that head is load-bearing.

### Compute budget

~15 minutes total (embedding is the bottleneck; all sklearn fits are <1s).

    heads = {}
    for dim in ['RD', 'DS', 'AMB', 'CR']:
        lr = LogisticRegression(C=1.0, max_iter=1000, random_state=seed)
        lr.fit(X_train, y_dim_train[dim])
        heads[dim] = lr
    # Stack head probabilities

        heads[d].predict_proba(X_train)[:, 1] for d in heads
    ])
    meta_features_test = np.column_stack([

    ])

    rf.fit(meta_features_train, y_route_train)
    return rf.predict(meta_features_test)
