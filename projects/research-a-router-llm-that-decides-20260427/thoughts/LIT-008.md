## Summary

FrugalGPT frames LLM cost-reduction as three strategies: prompt adaptation, LLM approximation, and LLM cascade. The cascade variant learns a scoring function (DistilBERT regressor) and sequentially invokes cheapest-to-most-expensive models, stopping when a reliability threshold is met. Achieves up to 98% cost reduction matching GPT-4 quality, or +4% accuracy improvement at same cost on several datasets.

## Key Claims

1. LLM cascade with learned scoring function outperforms any single LLM across cost levels on HEADLINES, OVERRULING, and COQA.
2. The cascade selects the cheapest model that meets a confidence threshold per query, explicitly optimizing cost subject to a quality constraint.
3. Constraint optimization over cascade ordering and thresholds is NP-hard; FrugalGPT uses a specialized pruning optimizer.
4. A reliability score (DistilBERT regressor on query × response) serves as the proxy reward for routing decisions — this is a supervised proxy, not direct RL optimization.

## Relevance to HYP-004

FrugalGPT's scoring function is analogous to the DeBERTa judge in HYP-004 but used in a threshold-cascade setting, not direct policy training. The key difference: FrugalGPT trains the scoring function supervisedly (regression against binary correctness labels), whereas HYP-004 uses the judge as an online reward signal in REINFORCE. This confirms there is no existing work doing RL-based single-call routing with direct judge reward.

## Limitations Noted by Authors

- Cascade must call multiple LLMs sequentially; higher latency than single-call routing.
- Learned cascade is dataset-specific; does not generalize to out-of-domain queries.
- Scoring function requires task-specific labeled data for training.
