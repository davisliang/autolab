## Motivation

Most cascade routing systems use a fixed confidence threshold to decide whether to escalate. But optimal thresholds vary by query domain, difficulty distribution, and user quality tolerance. Fixed thresholds either waste money (too high → escalates too often) or sacrifice quality (too low → accepts bad Haiku answers).

Calibrated confidence routing applies Platt scaling—a technique from probability calibration literature—to dynamically tune thresholds that minimize cost subject to a quality constraint, adapting online as the query distribution shifts.

## Claim

A cascade router with Platt-scaled dynamic thresholding (updated on a rolling 100-query window) achieves ≥20% lower total API cost than a fixed-threshold cascade router, both calibrated to the same target quality level (accuracy within 1pp of Sonnet-only baseline) on a mixed MMLU + GSM8K stream of 2,000 queries.

## Key Mechanism

1. Haiku generates a response and self-reports confidence (1–10 via prompt elicitation)
2. A Platt scaler maps raw confidence to calibrated P(correct)
3. Escalate to Sonnet if calibrated P(correct) < threshold; escalate to Opus if Sonnet also falls below a second threshold
4. Threshold updated every 100 queries via gradient descent on cross-entropy loss from answer-checker feedback

## Why ≥20%?

- Fixed-threshold systems typically over-escalate 10–30% due to poor calibration under distribution shift
- Dynamic calibration corrects for domain shift within a session (e.g., MMLU→GSM8K transition)
- Calibration experiments in NLP routinely show 15–40% efficiency gains from proper uncertainty quantification
- 20% is a conservative mid-range pre-registration

## Experimental Design Notes

- Dataset: 2,000 queries = 1,000 MMLU + 1,000 GSM8K, interleaved in random order
- Baseline: fixed-threshold cascade (threshold=0.6 Haiku confidence; tuned on separate calibration split of 200 queries)
- Dynamic router: Platt scaler updated online; threshold search every 100 queries against rolling quality target
- Confidence signal: Haiku prompted "Rate your confidence in your answer from 1 to 10" — extract integer
- Quality ground truth: regex answer checker for GSM8K; multiple-choice comparison for MMLU
- Seeds: 3 random query orderings × 3 initial threshold values = 9 runs
- Metrics: total USD API cost, average accuracy, cost-accuracy Pareto frontier

## Open Questions

- Is Haiku's self-reported confidence well-calibrated enough to be useful?
- Does Platt scaling on 100-query windows converge fast enough for short sessions?
- What happens at domain transition boundaries mid-stream?
