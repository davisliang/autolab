## Relevance to HYP-003

ComplexityNet is the closest prior art for HYP-003's core mechanism. Both works:
- Define oracle complexity labels as "cheapest model that solves each task"
- Train a lightweight classifier to predict these complexity labels at routing time
- Evaluate via routing accuracy vs. oracle labels

Key difference: ComplexityNet fine-tunes a small LM (opaque, no interpretable features) while HYP-003 proposes logistic regression over explicit multi-signal features (embedding clusters + syntax features). This makes HYP-003 an **interpretable, feature-engineered alternative** to ComplexityNet.

## Cost-Efficiency Baseline (addressing CRIT-004)

ComplexityNet reports 90% compute reduction at 86.7% quality — this is the correct cost-efficiency metric. CRIT-004 criticizes HYP-003 for measuring routing accuracy instead of cost efficiency. ComplexityNet validates that criticism: cost-efficiency is the target metric, not routing accuracy in isolation.

HYP-003's ≥85% routing accuracy claim must therefore be translated to: "what compute reduction does 85% routing accuracy yield?" Given ComplexityNet achieves 90% compute reduction at 79% routing accuracy, HYP-003 at 85% should yield even higher compute reduction — this is the re-framing needed.

## Limitation of ComplexityNet Relevant to HYP-003

ComplexityNet evaluates only on MBPP (coding). It does not evaluate on MMLU (multi-domain general knowledge). HYP-003 fills this gap by evaluating multi-signal routing on MMLU's diverse subject domains, testing whether complexity features generalize across reasoning types.

Also, ComplexityNet uses a fine-tuned LM (opaque) — it cannot tell you *why* a task is complex. HYP-003's logistic regression provides interpretable feature coefficients, enabling actionable insights about which features drive routing decisions.
