## Experiment Design: Entropy-Router vs Text-Feature Router

### Overview

Compare two routing strategies for a small→large model cascade:

1. **Entropy router** (HYP-001): Send query to small model, compute mean token-level entropy from logprobs. If entropy > learned threshold, escalate to large model.
2. **Text-feature router** (baseline): Train a TF-IDF + logistic regression classifier on input text features to predict when the small model will fail, then escalate.

### Models

- **Small model** ("Haiku proxy"): `Qwen2.5-0.5B-Instruct-4bit` via MLX — fast, cheap inference.
- **Large model** ("Opus proxy"): `Qwen2.5-3B-Instruct-4bit` via MLX — higher quality, 6x cost proxy.

Cost model: cost(small) = 1 unit, cost(large) = 6 units. Queries routed to large pay small+large = 7 units (entropy router already ran small). Text-feature router pays only large = 6 units when escalating.

### Dataset

**MMLU-lite**: 500 stratified-sampled questions from MMLU (5 questions × 57 subjects, plus extras from high-variance subjects). Multiple-choice format enables unambiguous correctness scoring. Downloaded from HuggingFace `cais/mmlu` (all split).

Calibration/test split: 60% calibration (train thresholds/classifier), 40% held-out test.

### Protocol

For each seed:

1. **Generate small-model responses** for all 500 questions. Record per-token logprobs.
2. **Generate large-model responses** for all 500 questions (needed for oracle comparison).
3. **Score correctness** by exact-match on MMLU answer letter.
4. **Train entropy router**: On calibration set, sweep entropy thresholds [0.1, 0.2, ..., 2.0] to find threshold maximizing quality_at_budget_normalized.
5. **Train text-feature router**: On calibration set, fit TF-IDF (unigram+bigram, max 5000 features) + LogisticRegression to predict small-model failure. Calibrate probability threshold to match entropy router's escalation rate (fair cost comparison).
6. **Evaluate on held-out test set**: Compute accuracy and cost for both routers at 5 budget points (escalation rates: 10%, 25%, 50%, 75%, 100%).
7. **Compute quality_at_budget_normalized** = mean over budget points of (accuracy / normalized_cost).

### Metric Definitions

- `accuracy_*`: fraction of correct answers under each routing strategy
- `cost_ratio_*`: average cost per query / cost_of_all_small (lower = cheaper)
- `quality_at_budget_normalized`: primary metric from HYP-001. Mean of (accuracy_at_budget / (cost_at_budget / cost_all_large)) across 5 budget points. Higher is better — rewards quality per unit cost.

### Pre-registered prediction

Entropy router achieves quality_at_budget_normalized ≥ 0.05 above text-feature router (direction: greater).

### Seeds and reproducibility

Seeds [42, 123, 456] control: calibration/test split, any model sampling temperature (set to 0 for deterministic generation where possible, temperature=0.01 with seed otherwise), and TF-IDF/LogReg random state.

### Compute budget

30 minutes total. ~500 queries × 2 models × ~1s each ≈ 17 min generation + overhead for training/evaluation.

### Addressing CRIT-002 concerns

The critique notes this is an incremental empirical study. The experiment addresses this by:
- Direct head-to-head comparison on identical data (not done in prior work)
- Multiple budget points (not just one operating point)
- Per-subject breakdown to identify where entropy routing wins/loses
