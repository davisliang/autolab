## Experiment: Selective Speculation — Hybrid Pre-Screen + Output-Verified Cascade (HYP-002 Retreat)

### Why this is materially different from EXP-001

EXP-001 tested "always speculate": run Haiku on every query, then judge. This failed because structural overhead (Haiku+judge=1.2 on ALL queries, including hard ones that always escalate) dominated the output-quality information advantage. The delta was -5.72pp vs the +8pp threshold.

**This experiment changes the mechanism**: instead of always speculating, we add a cheap input-feature pre-screen that triages queries into three zones:
1. **Easy zone** (difficulty < low_threshold): Route directly to Haiku. No judge needed — high confidence it's correct.
2. **Ambiguous zone** (low_threshold ≤ difficulty < high_threshold): Run Haiku + judge (speculative cascade). This is where output-quality signals add value over input-only routing.
3. **Hard zone** (difficulty ≥ high_threshold): Route directly to Sonnet. Skip Haiku entirely — avoids the 24% structural overhead on queries that would almost certainly escalate.

This eliminates the key failure mode: hard queries no longer pay 6.2 (Haiku+judge+Sonnet) vs 5.0 (direct Sonnet). The ambiguous zone is the only place we "speculate," and it's precisely where seeing output quality should matter most.

### Design

**Proposed (selective speculation)**:
1. Input-feature pre-screen estimates difficulty with noise σ=0.10
2. Easy zone: Haiku direct (cost=1.0)
3. Ambiguous zone: Haiku (1.0) + judge (0.2) → accept or escalate to Sonnet (5.0)
4. Hard zone: Sonnet direct (cost=5.0)
5. Sweep ambiguous band width: 0.10→0.40 (controls what fraction of queries get speculated on)

**Baseline (pure input-feature router)** — identical to EXP-001 baseline:
1. Router estimates difficulty with noise σ=0.10
2. Routes to Haiku or Sonnet based on threshold
3. Sweep threshold: 0.10→0.55

### Simulation Model (identical to EXP-001 for comparability)
- N=1319 questions (GSM8K test set size)
- Difficulty ~ Beta(2,3), mean≈0.40
- Haiku solves with P = sigmoid(-(d-0.35)/0.05), ~43% overall accuracy
- Sonnet solves with P = sigmoid(-(d-0.60)/0.05), ~80% overall accuracy
- Shared model outcomes across sweeps for fair comparison

### Key Prediction
The selective speculation approach eliminates structural overhead on ~40-60% of queries (the hard zone), retains information advantage on ~20-40% (ambiguous zone), and saves judge cost on ~20% (easy zone). Net effect should flip the sign vs EXP-001: proposed should outperform baseline by ≥8pp cost savings.

### Metrics
- **cost_savings_pp_vs_feature_router**: proposed savings minus baseline savings at matched quality (pp). Threshold: ≥8pp.
- **accuracy_delta_vs_sonnet_pp**: must be ≥ -2pp
- **proposed_savings_pp**: absolute cost savings vs always-Sonnet
- **baseline_savings_pp**: absolute cost savings vs always-Sonnet
- **ambiguous_zone_fraction**: fraction of queries routed through speculative cascade

[42, 123, 456] — 3 independent difficulty/outcome draws.

Trains a simple logistic classifier on 32 examples to predict Haiku correctness from difficulty features. Verifies cross-entropy loss drops ≥50%. Unlike EXP-001's trivial gate, this tests actual discrimination.
