## Motivation

Every routing paper in the literature (FrugalGPT, RouteLLM, HybridLLM, AutoMix, RouterBench, EcoAssistant) trains a router offline on a fixed dataset and deploys it frozen. None address the deployment reality that query distributions shift over time: a router trained on MMLU degrades when users pivot to math-heavy queries (GSM8K) or coding tasks.

**The question conspicuously absent from the literature**: Can a router that observes its own deployment outcomes and updates its policy online recover from distribution shift and improve cost efficiency beyond what a static router achieves?

This gap matters because:
1. Real deployments experience distribution drift — topic shifts, seasonal patterns, new user cohorts.
2. Static router thresholds are tuned on validation sets that become unrepresentative over time.
3. The bandit framing is natural: each routing decision is an arm pull (Haiku/Sonnet/Opus), the reward is correctness, and the cost is subtracted — yielding a cost-adjusted reward signal.
4. Contextual bandits (epsilon-greedy or LinUCB over embedding context) require no ground-truth labels at training time, only outcomes — consistent with real deployment where answers are judged post-hoc (user feedback, downstream pipeline success).

## Cross-Domain Transplant

This hypothesis transplants **contextual multi-armed bandits** (Thompson sampling / LinUCB from the online learning literature) into LLM routing. The bandit literature shows that contextual bandits recover from distribution shift within O(√T) regret, where T is the number of queries. For T=500 queries in a deployment stream, a bandit router should adapt its threshold to the new distribution, reducing escalation to expensive models faster than a static router.

Prior work in recommendation systems (Netflix, contextual ads) shows bandits adapt to distribution shift 40-60% faster than offline-trained models on new cohorts. HYP-006 transplants this finding to the LLM routing domain.

## Proposed Experiment Design

**Phase 1 (offline training, 1000 queries)**: Train a base static logistic-regression router on MMLU sentence embeddings → {Haiku, Sonnet, Opus} labels. Freeze this as the static baseline.

**Phase 2 (online deployment stream, 500 queries)**:
- Stream: First 250 queries from MMLU (in-distribution), next 250 from GSM8K (distribution shift)
- Bandit router: LinUCB with embedding context, initialized from static router weights; updates thresholds after each query using observed reward (oracle correctness check on answer)
- Static router: same base, no updates, thresholds frozen

**Cost model**: Haiku=1 unit, Sonnet=5 units, Opus=15 units. Expected cost = sum(tier_cost × indicator) / n_queries.

**Primary metric**: `incremental_cost_reduction_pct_over_static_router` = (static_cost − bandit_cost) / static_cost × 100, measured over the final 100 queries (after adaptation) at accuracy ≥80%.

**Baselines**: (a) static router, (b) always-Haiku, (c) always-Opus, (d) oracle routing.

**Seeds**: 3 seeds controlling query permutation order and bandit initialization noise.

## Why This Is Novel

The LLM routing literature is entirely offline. No paper has studied whether a router can adapt online to deployment feedback. The bandit framing is novel in this context and directly addresses a real production concern (distribution shift) with a lightweight, interpretable update mechanism. Unlike full model retraining, LinUCB updates in O(d²) time per query (d = embedding dimension), adding negligible overhead.

## Pre-registration Contract

- **Metric**: incremental cost reduction (%) of bandit router over static router, measured on final 100 queries of the distribution-shifted stream, at accuracy ≥80%
- **Threshold**: ≥15.0 percentage points incremental cost reduction
- **Direction**: greater (bandit strictly better than static after distribution shift adaptation)
- **Falsification criterion**: If bandit cost reduction ≤15pp over static router, or accuracy drops below 80%, the hypothesis fails — suggesting that 500-query online adaptation is insufficient for LLM routing, or that the static router is already robust to the tested distribution shift.
