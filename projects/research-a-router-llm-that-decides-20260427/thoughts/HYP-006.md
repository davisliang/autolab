## Gap Identification

All 25 LitFindings describe **static, offline-trained routers**: RouteLLM trains on Chatbot Arena preference data once; FrugalGPT fits a scoring function on a held-out calibration set; AutoMix solves a POMDP on 50 fixed examples. None of the surveyed literature considers what happens when the query distribution drifts (new user cohorts, new task domains, provider API changes). RouterBench (LIT-005) explicitly notes "routing generalization across task domains is an open challenge," yet proposes no adaptive solution.

The **online learning / multi-armed bandit** literature (Thompson Sampling, UCB, LinUCB) is entirely absent from the LitFinding set. These algorithms update a policy after every observed outcome — exactly the problem structure of LLM routing: a router selects a model (arm), observes quality feedback (LLM-as-judge score), and updates its policy. This is a direct cross-domain transplant from contextual-bandit literature into LLM routing.

## Mechanism

1. **Context vector**: encode each incoming query as a low-dimensional embedding (e.g., via a small frozen encoder like sentence-transformers).
2. **Bandit arms**: {Haiku, Sonnet, Opus} — three arms.
3. **Thompson Sampling policy**: maintain per-arm Beta/Gaussian posteriors conditioned on context. On each query, sample from posteriors and pick the arm with highest expected reward.
4. **Reward signal**: after the model responds, an LLM-as-judge (fast Haiku judge) scores quality (0–1). Reward = quality − α × normalized_cost, where α balances quality vs. cost.
5. **Update**: update the arm's posterior with the observed (context, reward) pair — no batch collection required.

## Why This Is Novel

- **Static vs. online**: all prior routers require collecting a new labeled dataset and retraining when distribution shifts. The bandit router updates in <1ms per query.
- **No preference labels**: unlike RouteLLM, the bandit needs only post-hoc quality scores (LLM judge), not pairwise human preference annotations.
- **Distribution shift robustness**: Thompson Sampling naturally "forgets" stale beliefs by reweighting context-conditioned posteriors. A static router has no such mechanism.

## Cross-Domain Transplant

This hypothesis transplants **contextual multi-armed bandits** (Agrawal & Goyal 2013 Thompson Sampling; Li et al. 2010 LinUCB) from recommendation systems and clinical trial optimization directly into the LLM routing setting. The analogy: query = user context, model arm = treatment, quality score = outcome.

## Experiment Sketch

- **Baseline**: RouteLLM static router trained on 2k Chatbot Arena examples (LIT-001/LIT-007 protocol).
- **Proposed**: contextual Thompson Sampling router with sentence-transformer context encoder, initialized with uniform priors.
- **Distribution shift protocol**: train baseline on general-knowledge queries; evaluate both on a held-out coding + math distribution (out-of-domain).
- **Metric**: quality-cost AUC on out-of-distribution set after N=500 online queries.
- **Seeds**: 3+ (random initializations of bandit priors).

## Pre-registered Prediction

The online contextual-bandit router achieves quality-cost AUC ≥ 0.08 higher than the static RouteLLM baseline on the out-of-distribution evaluation set, measured after 500 online adaptation queries.
