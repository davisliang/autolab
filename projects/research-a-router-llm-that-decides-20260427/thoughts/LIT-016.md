## Summary

Chen, Zaharia, and Zou (2023) from Stanford outline three cost-reduction strategies for LLM APIs: prompt adaptation, LLM approximation, and LLM cascade. FrugalGPT implements the cascade approach: sequentially query models in cost order (cheap → expensive) and stop when a learned reliability scorer is satisfied. The reliability scorer is trained per-task on response quality labels. They achieve 98% cost reduction vs. GPT-4 alone at matched accuracy on HEADLINES; 4% accuracy improvement at matched cost on other tasks.

## Key Claims

1. LLM cascade (sequential query until reliability threshold met) can match GPT-4 performance with up to 98% cost reduction.
2. The cascade's stopping criterion is a per-query reliability score estimated from response features — functionally similar to output-side confidence.
3. The reliability scorer requires labeled training data and per-task calibration — it does not generalize zero-shot to new tasks.
4. Cascade latency doubles when a query escalates (two sequential calls); entropy-based routing avoids this by deciding post-Haiku-call rather than triggering a new call cycle.

## Relevance to HYP-001

FrugalGPT represents the cascade baseline in HYP-001's setup. The FrugalGPT reliability scorer is conceptually adjacent to HYP-001's entropy threshold: both use output-side features to decide escalation. The key difference is that FrugalGPT's scorer requires supervised labels per domain, while HYP-001's entropy threshold requires only a small calibration set on the target quality metric — making it more broadly applicable. The 98% cost reduction benchmark sets a strong upper bound for cascade approaches that HYP-001 must approach.
