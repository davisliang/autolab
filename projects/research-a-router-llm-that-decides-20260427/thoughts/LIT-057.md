## Summary

Hybrid LLM (Mallick et al., 2024, Microsoft) trains a DeBERTa encoder to predict the quality gap (BART score difference) between a small edge model and a large cloud model. Routing threshold is tunable at test time; 40% fewer large-model calls with no quality drop. Key innovation: using soft probabilistic labels (average over 10 responses per query) rather than hard binary oracle labels.

The model predicts from input features alone — no model output required at routing time. This validates the input-feature-only approach HYP-003 uses. The finding that soft labels outperform hard labels is important: HYP-003 uses hard binary oracle labels (cheapest model achieving ≥90% of Opus score), which may introduce label noise on queries near the quality threshold.

## Key Claims

1. A DeBERTa router predicting quality gap from input features alone achieves 40% reduction in large-model calls with no quality drop — validates input-feature routing.
2. Soft probabilistic labels (10-response average) substantially outperform hard binary labels by modelling response stochasticity: quality gap near the decision boundary is ambiguous.
3. Data transformation (shifting labels when models differ greatly) improves routing when models span a wide quality range (analogous to Haiku→Opus gap).
4. "Easy" queries (small quality gap) can be reliably identified from input features; "hard" queries (large gap) are harder to detect from input alone.

## Relevance to HYP-003

Hybrid LLM provides two specific lessons for HYP-003:
1. **Label strategy**: HYP-003's hard binary oracle labels (≥90% threshold) may have high variance near the threshold. Soft labels averaging multiple runs would reduce noise but increase data collection cost.
2. **Feature validation**: DeBERTa on input text (a much richer feature representation than HYP-003's hand-crafted features) achieves 40% savings. HYP-003's logistic regression with hand-crafted features is likely to achieve less savings — setting a realistic upper bound.

## Limitations

- DeBERTa is far heavier than HYP-003's LR; routing overhead may be significant at scale.
- Soft labels require multiple LLM inference calls per training query — impractical in low-data settings.
- Binary routing (small vs large); 3-tier extension is non-trivial.
