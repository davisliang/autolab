## Summary

AutoMix introduces a POMDP-based router for N-way LLM routing that uses few-shot self-verification as noisy observations of query difficulty. The POMDP agent learns routing policy that maps belief states (posterior over query difficulty given self-verification outputs) to model choices. Trained with as few as 50 examples. Reduces cost by 50%+ with comparable performance across 5 datasets.

## Key Claims

1. POMDP formulation handles noisy verification signals better than a deterministic threshold router — the Bayesian belief state smooths out self-verification noise.
2. Self-verification (framed as NLI entailment) provides a task-agnostic quality signal without requiring gold labels or response quality annotations.
3. 50-shot learning is sufficient for the POMDP policy to outperform supervised verifier baselines.
4. AutoMix reduces cost by 2x at matched performance across QASPER, QuALITY, QUALITY, CoQA, and SummScreenFD.

## Relevance to HYP-004

AutoMix is the closest existing work to RL-based routing: it formulates routing as a sequential decision problem (POMDP) and learns a policy from quality signals. However, it uses **belief-state planning** (solved via value iteration) rather than **policy gradient / REINFORCE** optimization. AutoMix also uses self-verification (same small model checking its own output) rather than an independent judge reward. HYP-004 differs by: (a) using REINFORCE with an external judge, (b) directly optimizing quality-minus-cost reward, (c) targeting 3-way routing (Haiku/Sonnet/Opus). AutoMix's success validates that sequential decision / policy formulations are feasible for LLM routing and can outperform supervised baselines.

## Limitations Noted by Authors

- Self-verification is noisy for reasoning tasks (POMDP partially compensates).
- Requires sequential model calls (slower than single-call routing).
- POMDP solution requires discretizing belief states; does not scale trivially to many models.
