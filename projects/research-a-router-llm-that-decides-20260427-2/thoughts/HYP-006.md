## Hypothesis HYP-006: Online Bandit Routing Under Distribution Shift

### The Gap

RouterBench (LIT-014) explicitly documents that **prior routers fail to generalize across datasets** — showing 2–5x variation in optimal model selection across domains and noting that a router trained on MMLU degrades on coding benchmarks. Every existing routing system (FrugalGPT, RouteLLM, AutoMix, Hybrid LLM) trains offline and deploys a static policy that cannot update from deployment-time observations.

The gap: **no paper proposes online adaptation of the routing policy** using observed outcomes. This is a critical practical failure mode — in production, query distributions shift (new product features, seasonal patterns, user base evolution), but the router is frozen.

### Cross-Domain Transplant: Recommender System Bandits

This transplant comes from **contextual multi-armed bandits in recommender systems** — specifically Thompson Sampling with Beta-distribution posteriors, which is the standard approach for online A/B exploration in click-through-rate optimization (Chapelle & Li, 2011; the technique predates LLM routing by a decade). In that domain:
- Arm = content item / recommendation
- Reward = click (binary)
- Challenge = exploration vs exploitation under distribution shift

Transplanted to LLM routing:
- Arm = {Haiku, Sonnet, Opus}
- Reward = quality(query, model) ∈ {0, 1} (binarized at quality threshold)
- Context = query embedding (LinThompson for contextual variant)
- Challenge = adapt to distribution shift without storing full re-training pipeline

### Mechanism

Maintain per-arm Beta posteriors Beta(α_k, β_k) representing the estimated quality rate of model k. At each routing decision:
1. Sample θ_k ~ Beta(α_k, β_k) for each model
2. Route to argmax_k [θ_k / cost_k] (quality-per-dollar Thompson sample)
3. Observe quality feedback (e.g., user thumbs up/down, or auto-eval score)
4. Update: if quality ≥ threshold → α_k += 1, else β_k += 1

For distribution shift simulation: use RouterBench split where first 50% queries are MMLU, second 50% are HumanEval coding. Static router trained on MMLU degrades on coding; bandit router adapts.

Baseline: a static RouteLLM router trained offline on the pre-shift distribution (frozen).

### Why This Wasn't Done Before

All prior router papers treat routing as a one-shot supervised or RL problem on a fixed offline dataset. The bandit framing requires observable feedback at inference time, which most offline benchmarks don't provide. RouterBench's pre-cached format is perfect for simulating this: it stores ground-truth correctness labels, so we can simulate the feedback loop by revealing the cached outcome after each routing decision.

### Predicted Outcome

Cumulative routing regret (total quality-per-dollar shortfall vs oracle optimal routing) decreases ≥20% relative to the static offline baseline on the domain-shift simulation. The advantage concentrates in the post-shift segment (queries 50%–100%), where the bandit adapts within ~200 queries and the static router stays miscalibrated.

### Pre-registered Prediction

- **Metric**: cumulative_routing_regret_reduction (relative %, lower regret = higher value)
- **Threshold**: ≥0.20 (20% relative reduction in cumulative regret vs static baseline)
- **Direction**: greater
